2017 → now

Standard attention solved one problem. Everything after attacked the bills it created.

Until attention, a token could be a beautiful vector and still know nothing about its neighbors. Attention is where tokens start interacting. Later mechanisms appear here in the order they launched, each responding to a cost that came before.

We start with the ordinary mechanism, then follow what got expensive once context grew: pairwise compute, KV-cache memory, and the need for position.

Q × Kscores ÷ √dₖscale + Mmask softmaxweights × Vmix outputvector
2017-06 exact global

Scaled dot-product attention

Vaswani et al., Attention Is All You Need · arXiv:1706.03762 · submitted 12 Jun 2017

One token x becomes three projections: query (what am I looking for?), key (what do I contain?), value (what should I give you if you choose me?). When the model processes sat, its query may match the key for cat, so more of cat's value flows into sat. 

Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V
Causal:             softmax(QKᵀ / √dₖ + M) V
                    M = 0 allowed, −∞ future

Read inside-out: scores, scale so logits stay in a useful range for softmax, mask futures during causal training, turn each row into weights that sum to one, then take a weighted sum of values.

Lab · five steps on four tokens

Walk the pipeline. Toggle the causal mask to see weight leak into the future.

Lab · why √dₖ exists

Raise the head width. Unscaled dots start collapsing the softmax.

What it buys

Exact, query-specific selection over the whole allowed context. Positive weights that sum to one. Parallel training with a causal mask.

What it gives up

Compute grows ≈ T². Decode must keep a growing KV list. And content alone carries no order—two identical words at different positions look the same.

When I'd choose it

Default when context is short enough that exact all-pairs is affordable and quality matters more than serving memory. Still the reference every later method is measured against.

The field now faces two bills: pairwise compute that grows with T², and a per-conversation KV cache that grows with T. Position is still unsolved.

2017-06 position

Sinusoidal positional encodings

Same Transformer paper · absolute geometric frequencies · no learned position table

Attention compares content. The causal mask blocks the future, but among allowed tokens the score still needs a distance clue. The Transformer adds a fixed sinusoid of wavelength that grows geometrically across dimensions, then adds it to the token embedding. 

PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))

What it buys

Order without a learned table. Deterministic for any integer position. The paper hoped this would help extrapolation.

What it gives up

Absolute coordinates, not relative distances inside the score. Extrapolation beyond the training length was weaker than hoped. Many later models quietly dropped it.

When I'd choose it

Historical baseline, or a fixed PE when you refuse a learned table and do not yet want rotary relative geometry.

Practitioners wanted positions the model could adapt. That pressure produced learned absolute embeddings.

2018-06 position

Absolute learned positions

Radford et al., GPT-1 · OpenAI, 11 Jun 2018 · also BERT (Oct 2018)

GPT-1 follows the Transformer but replaces the sinusoid with a trainable table Wₚ indexed by position and added to the token embedding. Inside a fixed max length this often trains cleaner than a frozen geometric pattern. 

h₀ = token_embed(x) + Wₚ[0…T−1]

What it buys

Flexible absolute position features learned from data. Strong inside the training length.

What it gives up

A hard wall: there is no embedding for position max_len+1. Relative “six behind me” is not built into the score. Long-context extension is blocked until you change the PE.

When I'd choose it

Short, fixed windows (classic BERT/GPT lengths). Not a candidate for stretch-to-million serving.

Position was patched for short windows. The T² compute bill was still open. Sparse patterns attacked that next.

2019-04 sparse

Sparse and top-k attention

Child et al., Generating Long Sequences with Sparse Transformers · arXiv:1904.10509 · 23 Apr 2019

Keep softmax. Stop reading every key. Factorized sparse patterns (or later top-k selection) let each query use a small subset of positions. Full attention uses T values; top-k uses k ≪ T after selection. 

score all candidates → keep best k → softmax only on those k → mix those k values

The catch the session emphasizes: naïve top-k still scores every key first. If scoring was the expensive part, you have not solved it. Practical systems need a cheap proposal step—local window, router, or compressed index—then exact attention only on candidates.

What it buys

Sub-quadratic patterns while keeping exact softmax on the survivors. Long sequences become trainable again when most mass is concentrated.

What it gives up

Dropped keys never contribute. Proposal errors are silent. Kernel and routing complexity rise. Sparse is not “full attention with zeros deleted”—it is a candidate search problem.

When I'd choose it

Long documents where local/strided patterns or a trained indexer are good enough, and you still want softmax fidelity on the chosen set.

Sparse attacks compute. Serving still stores a key and value per earlier token. Multi-query attention attacked that decode bill.

2019-11 memory

Multi-query attention (MQA)

Shazeer, Fast Transformer Decoding: One Write-Head is All You Need · arXiv:1911.02150 · 6 Nov 2019

Prefill is expensive because of QKᵀ. Decode is often memory-bound because every new token reloads the entire KV history. MQA keeps many query heads but stores a single shared K/V head. Cache bytes drop by roughly the old head count. 

cache ∝ 2 × layers × kv_heads × head_dim × T × bytes
MQA: kv_heads = 1

Lab · head sharing and the cache slope

Same eight query heads. Change how many K/V heads they share.

What it buys

Much smaller KV traffic at decode. Higher tokens/sec on memory-bound hardware.

What it gives up

Quality can drop when every query head is forced through one key/value view. Prefill QKᵀ is still quadratic. Cache still grows linearly with T.

When I'd choose it

Latency-critical decode where quality loss is acceptable, or as the extreme of a GQA search. Not a full long-context solution by itself.

MQA lowers the slope of the cache line. The line still rises with every token. Sliding windows tried to cut which positions stay live.

2020-04 sparse

Sliding-window attention

Beltagy et al., Longformer · arXiv:2004.05150 · 10 Apr 2020 · later Mistral 7B (Oct 2023)

Each token attends only inside a local window of width w (plus optional global tokens). Cost falls from O(T²) toward O(T·w). Stacked layers expand the receptive field without one global dense layer.

What it buys

Linear-ish attention compute and a bounded cache if you truly drop tokens outside the window.

What it gives up

Direct long-range edges. Information must hop across layers. Streaming with a hard window later revealed the sink failure (2023).

When I'd choose it

Local-structure documents, or hybrid stacks where most layers are windowed and a few remain global/sparse.

Windows still use softmax over a subset. Another 2020 idea asked: what if we remove softmax entirely and fold history into a fixed matrix?

2020-06 recurrent

Linear attention

Katharopoulos et al., Transformers are RNNs · arXiv:2006.16236 · 29 Jun 2020

Softmax ties scores through a shared denominator, so each new query needs the individual old keys. Drop softmax and the distributive law lets you pre-combine history: 

direct:    y = Σⱼ (q · kⱼ) vⱼ
regrouped: S = Σⱼ vⱼ kⱼᵀ     (fixed-size state)
           y = S q

after 10 tokens     → one d×d matrix
after 1,000,000     → still one d×d matrix

Softmax was doing real work: positive weights, unit sum, competition, query-specific distributions. Removing it buys a fixed state and linear sequence work. It also creates interference: add-only writes accumulate old contributions forever.

What it buys

O(T) sequence work and O(1) state size instead of a growing KV list. Cheap long training and serving when the state is enough.

What it gives up

Exact token-by-token lookup. Unnormalised scores. Memory interference under naïve additive writes. Often weaker associative recall than softmax.

When I'd choose it

When you can afford lossy memory and need extreme length or throughput—especially later, hybridized with occasional softmax/sparse layers.

Linear attention reopened recurrent state. The next years mostly chased position and cache; the write-rule repair (delta) returned in 2024. First, relative position got a clean geometric fix.

2021-04 position

RoPE — rotary position embedding

Su et al., RoFormer · arXiv:2104.09864 · 20 Apr 2021

Treat pairs of dimensions as 2D arrows. Rotate the query at position i by iθ and the key at j by jθ. Absolute rotations cancel in the dot product; only the relative angle i−j remains. 

R(iθ)q · R(jθ)k = q · R((j−i)θ)k

Lab · relative angle survives absolute shift

Change the gap. The positional contribution depends on distance, not absolute index.

What it buys

Relative distance inside the score. No finite lookup table. Became the default in modern decoder LMs.

What it gives up

Defined beyond training length ≠ competent beyond training length. Far positions can repeat phase patterns the model never learned. Stretching RoPE later needed NTK/YaRN/DroPE.

When I'd choose it

Almost always as the base PE for decoder LMs today—then decide separately how to extend past the trained length.

RoPE still embeds position into vectors. ALiBi asked whether the bias could sit directly on the scores instead.

2021-08 position

ALiBi

Press et al., Train Short, Test Long · arXiv:2108.12409 · 27 Aug 2021

No position embeddings in the residual stream. Before softmax, subtract a head-specific slope times the distance: nearer tokens keep higher scores, farther tokens are linearly penalized. Different heads get different slopes. 

scoreᵢⱼ += −mₕ · (i − j)   for j ≤ i

Lab · steeper slopes forget faster

What it buys

Strong length extrapolation after short training. Simple. No PE table to exhaust.

What it gives up

Less expressive than learned rotary geometry for some tasks. Static linear distance bias; not content-adaptive. Later industry mostly standardized on RoPE + scaling instead.

When I'd choose it

When you want short-train / long-test with minimal PE machinery, or as a strong ablation against RoPE scaling.

By 2023, MQA’s quality hit and MHA’s cache cost forced a compromise: share KVs in groups, not all-or-one.

2023-05 memory

Grouped-query attention (GQA)

Ainslie et al., GQA · arXiv:2305.13245 · 22 May 2023

Several query heads share one K/V head. Cache shrinks versus MHA; quality usually holds better than pure MQA. The session’s point: GQA is a baseline, not the answer. It changes how much you store per token. It still stores something for every token. 

MHA cache ∝ 8T
GQA cache ∝ 2T
MQA cache ∝ 1T
Double T → every line still doubles.

What it buys

Large decode-memory win with a milder quality trade than MQA. Easy retrofit from MHA checkpoints via continued training.

What it gives up

Linear growth with context remains. Prefill compute remains quadratic. At 1M tokens you still hold 1M positions.

When I'd choose it

Default head layout for almost every production decoder today. Necessary, not sufficient, for million-token serving.

Models standardized on RoPE+GQA. Then people tried to serve contexts longer than they trained—and RoPE phases broke. Community patches arrived within weeks.

2023-06 position

NTK-aware RoPE scaling

bloc97 · r/LocalLLaMA · 29 Jun 2023 · formalized in YaRN appendix

Linear position interpolation stretches every RoPE frequency equally and smears the high-frequency detail needed to tell nearby tokens apart. NTK-aware scaling changes the RoPE base so low frequencies stretch more and high frequencies stay closer to trained: 

b′ = b · s^{|D| / (|D| − 2)}
s  = L′ / L

Lab · who gets stretched

What it buys

Often usable longer context with little or no fine-tuning. Protects local (high-frequency) resolution better than naïve PI.

What it gives up

Some dimensions slightly extrapolate “out of bound.” Theoretical scale s understates the true extension; you often set s higher than the ratio you want. Fine-tuning can lag pure PI.

When I'd choose it

Zero-shot or light-touch extension of a RoPE model by a modest factor (roughly 2–8×) when you cannot retrain long.

NTK fixed the high-frequency damage of PI. YaRN mixed both ideas and added a temperature fix for attention entropy.

2023-08 position

YaRN

Peng et al., YaRN · arXiv:2309.00071 · submitted 31 Aug 2023

“NTK-by-parts”: leave the highest frequencies untouched, fully interpolate the slowest, ramp the middle. Then rescale attention logits by a temperature fitted to the scale factor so perplexity does not drift uniformly across the long window. 

√(1/t) ≈ 0.1 ln(s) + 1
attention → softmax(scores / t)

What it buys

Stronger extensions after fine-tuning on tiny data fractions. Dynamic YaRN can more than 2× extend at inference with no fine-tune.

What it gives up

Still a stretch of a short-trained model—there is a practical ceiling. Hyperparameters and ramp bands are empirical. Does not reduce KV cache or QK compute.

When I'd choose it

Road 1 from the session: train affordable lengths, then positional extension. Good when 8K→32K/64K-class jumps are the target.

Windows returned for streaming. Dropping early tokens without care broke models—even when the recent window still fit.

2023-09 sparse

Attention sinks

Xiao et al., StreamingLLM · arXiv:2309.17453 · 29 Sep 2023

Softmax must put mass somewhere. Models dump a surprising share onto the first few tokens—attention sinks—even when those tokens are semantically dull. Evict them in a sliding cache and the distribution renormalizes badly. Keep a few sink tokens plus the recent window and streaming stabilizes.

Lab · window with and without sinks

What it buys

Infinite-stream generation with a finite cache, without retraining, if sinks + window are retained.

What it gives up

Middle history is gone. You cannot quote a dropped paragraph. Sinks are a crutch for stability, not understanding of the evicted span.

When I'd choose it

Chat/stream workloads that must run endlessly on a bounded cache and mostly need recent context plus stable softmax mass.

Cache pressure kept rising. DeepSeek-V2 compressed the latent KV itself—different axis from GQA’s head sharing.

2024-05 memory

Multi-head latent attention (MLA)

DeepSeek-AI, DeepSeek-V2 · arXiv:2405.04434 · 7 May 2024

Instead of storing full per-head K and V, MLA stores a low-rank latent joint compression and up-projects when attention needs them. RoPE dimensions are handled carefully so rotary and compressed paths coexist. Cache shrinks along the feature axis, not by deleting sequence positions.

What it buys

Large KV reductions versus ordinary MHA/GQA at similar quality. Lets huge MoE models keep longer contexts under a memory budget.

What it gives up

Implementation complexity. Low-rank bottlenecks can lose detail. Still one latent record per token—sequence length still multiplies memory.

When I'd choose it

When head-sharing alone is not enough cache relief but you still want dense softmax attention over positions.

Meanwhile the linear-attention line returned with a better write rule: stop adding the whole new answer; write only the correction.

2024-06 recurrent

Delta rule / DeltaNet

Yang et al., Parallelizing Linear Transformers with the Delta Rule · arXiv:2406.06484 · 10 Jun 2024 · (rule lineage: Schlag et al. 2021)

Additive linear state: new = old + write. If key A held 40 and should become 55, adding 55 yields 95. The delta rule reads first, then writes the residual: 

current 40, wanted 55 → delta +15 → 40+15 = 55
Sₜ = Sₜ₋₁ (I − βₜ kₜ kₜᵀ) + βₜ vₜ kₜᵀ

Lab · overwrite versus pile-on

Write A, then overwrite A. Additive state mixes; delta corrects.

What it buys

Updateable fixed-size memory. Better associative recall than add-only linear attention. Parallel chunkwise training made it scalable.

What it gives up

Still compressed—no exact token replay. Forgetting/clearing is limited without an explicit gate. Pure DeltaNet can lag gated SSMs on some real retrieval.

When I'd choose it

As the D layers in a hybrid schedule: cheap depth with occasional exact/sparse layers for direct reads.

Delta could rewrite associations. It still lacked fast, selective erasure. Gating returned for that.

2024-12 recurrent

Gated DeltaNet

Yang, Kautz, Hatamizadeh · arXiv:2412.06464 · 9 Dec 2024 · ICLR 2025

Combine Mamba2-style decay with the delta write. αₜ → 0 clears memory quickly; αₜ → 1 recovers pure delta updates. 

Sₜ = Sₜ₋₁ ( αₜ (I − βₜ kₜ kₜᵀ) ) + βₜ vₜ kₜᵀ

Hybrids in the paper interleave Gated DeltaNet with sliding-window or Mamba2 layers—the same “not every layer needs the same memory system” lesson as the session’s depth schedules.

What it buys

Targeted writes plus adaptive forgetting. Stronger language-modeling and recall than DeltaNet or Mamba2 alone in the reported suite.

What it gives up

More complex transition than plain SSMs. Still not exact attention. Hybrid KV from window layers reintroduces some cache.

When I'd choose it

Primary recurrent mixer when you want linear-time depth and can spend a minority of layers on window/sparse exact access.

Sparsity returned with training-aware, hardware-aligned designs—not post-hoc pruning.

2025-02 sparse

Native Sparse Attention (NSA)

Yuan et al. / DeepSeek-AI · arXiv:2502.11089 · 16 Feb 2025 · added beyond the minimum list

Hierarchical sparse attention trained end-to-end: compressed coarse tokens, selected fine blocks, and a sliding window, gated together. Designed so the sparsity pattern maps onto Tensor Cores instead of scattering memory access.

What it buys

Trainable sparsity with speedups in forward, backward, and decode at long lengths. Global sketch + local precision.

What it gives up

Engineering-heavy kernels. Selection can still miss. Compression loses token identity inside a block.

When I'd choose it

When you need long-context pretraining efficiency and can invest in native sparse kernels—not as a decode-only retrofit.

DeepSeek then pushed compression further: shrink the sequence, then sparsify the summaries.

2025-09 sparse

DeepSeek Sparse Attention (DSA)

DeepSeek-V3.2-Exp release · Sep 2025 · technical report arXiv:2512.02556 · 2 Dec 2025

Keep MLA’s latent KV path. Add a lightweight lightning indexer that scores context entries, then run fine-grained sparse attention only on the selected subset. Continues V3.1 with the same MoE backbone so the quality comparison is almost an architecture A/B on sparsity alone. 

indexer scores candidates → top-k sparse attention on survivors
(still token/latent entries — not yet block-compressed)

What it buys

Long-context FLOPs and serving cost drop while keeping near-parity on the V3.1 benchmark suite in the reported Exp release.

What it gives up

Indexer errors skip tokens. You still store history at token/latent granularity—memory shrinks less than sequence compression will. Training the indexer adds complexity.

When I'd choose it

When MLA+GQA cache is under control but dense attention compute at long T is not—and you want a sparse retrofit on an existing DeepSeek-style stack.

Sparse selection helped compute. Position generalization was still a separate road. DroPE attacked the PE scaffold next.

2025-12 position

DroPE

Gelberg et al. / Sakana AI · arXiv:2512.12167 · 13 Dec 2025

Observation: positional embeddings help optimization during pretraining, yet over-reliance blocks length generalization. DroPE pretrains with PE (typically RoPE), then drops positional embeddings and runs a short recalibration at the original context length. After that, zero-shot long context improves without long-context fine-tuning.

Align this with the session’s evidence boundary. A reported training story (e.g. 8K → 256K with positional recalibration before annealing) is evidence for that run. “Defined at 256K” is not “proven competent at 256K.” DroPE is one concrete algorithm in that family—not a magic inference switch.

What it buys

Road 1 made sharper: keep PE as a training scaffold, remove it so test-time length is less trapped by trained phases. Cheap relative to native long pretraining.

What it gives up

Needs a recalibration phase. Removes an inductive bias that helped training—done badly, short-context quality dips. Does not shrink KV or QK cost; it addresses position/generalization.

When I'd choose it

When you already have a strong short-context RoPE model and want large extension without paying full native long training—after measuring the ceiling for your target.

Stretching position is one road. The other is making million-token training cheap enough to do natively—by compressing the sequence, then sparsifying.

2026-04 sparse

Compressed Sparse Attention (CSA)

DeepSeek-V4 · arXiv:2606.19348 · 26 Apr 2026 · hybrid with Heavily Compressed Attention (HCA)

Two different savings stacked on top of DSA. Compress every m tokens into one KV summary (storage ↓). Then run the lightning indexer and keep only top-k summaries for expensive attention (reads ↓). V4 interleaves CSA with HCA (larger m′, dense on the compressed lane) plus a small recent window so a token is not blind inside its own block. 

T tokens → ~T/m compressed entries → top-k reads
indexer ranks; core attention mixes only survivors

Lab · compress, then select

What it buys

Road 2: architecture cheap enough to train and serve at extreme length. Reported V4 path makes ~1M-token context practical via hybrid CSA/HCA.

What it gives up

Token detail inside a block. Indexer mistakes skip whole regions. System complexity (cache layout, CP, mixed precision) explodes.

When I'd choose it

Native million-token agents/documents when stretch methods have hit their ceiling and you can pay the training/systems cost.
